ATFとAutomateProの役割分担

領域主担当ねらい
ServiceNow内で完結する基本回帰ATFAEMC/ReleaseOpsに組み込みやすい標準ゲートとして実行。
業務E2E、外部連携、実ユーザー視点AutomatePro AutoTestVisual playbackや実行証跡を活用し、UAT・回帰の信頼性を高める。
アップグレード・任意Pre-Prod全回帰ATF + AutomatePro内部品質と業務シナリオの両方を確認。
リリース判定ReleaseOpsDeployment Requestにテスト実行ID、結果URL、証跡を集約。

GitHubはXML全行レビューのためだけではない

変更追跡

要求、PR、Commit、アプリバージョン、Deployment Requestを相互参照。

レビュー統制

CODEOWNERS、必須レビュー、PRテンプレートで職務分離を実現。

差分検知

XML全体ではなく、スクリプト、ACL、データモデル、削除・追加など高リスク差分を重点確認。

XML資材の扱い

XML投入を一律に否定しない。sys_user、sys_user_group、ロール付与、カスタムマスターなど、更新セットに自然に載らないデータは、同期、Import Set、冪等な投入スクリプト、Runbook化、統制されたXML例外に分類する。

分類推奨アプローチ
設定・アプリ成果物スコープアプリまたは更新セットへ移し、ReleaseOpsで昇格。
マスター・データ系外部正本同期、Import Set/Transform Map、冪等スクリプトを検討。
残るXML例外Runbook taskでファイル識別、投入順、検証、証跡、復旧手順を管理。

段階的移行ロードマップ

  1. Phase 0: 棚卸し、標準設計、AutomateProのAPI/Webhook/実行方式確認。
  2. Phase 1: 小規模アプリでATF、AutomateProスモーク、Instance Scan、Runbookをパイロット。
  3. Phase 2: ReleaseOps標準経路化、AutomatePro結果のDeployment Request連携、昇格停止ルール運用。
  4. Phase 3: Developer Sandboxes、DevOps Change Velocity、補助自動化を拡張。
  5. Phase 4: ATF/AutomateProカバレッジ、XML例外、Playbookを継続改善。
